# アフィリエイト分析ダッシュボード

マネートラックの「成果リスト」と「すべてのクリック」の xlsx を放り込むと、
KPI・推移・アフィリエイター別・商品別・流入元・CVR を見られるダッシュボード。

- **フロント**: ビルド不要の静的サイト（HTML + ES モジュール）。GitHub Pages にそのまま置ける。
- **DB**: Supabase (Postgres)。集計は SQL 側の関数（RPC）で行い、ブラウザには集計後の小さな結果だけ返す。
- **IPアドレスは保存しない**。取り込み時にブラウザ側で列ごと捨てている。
- **同じデータは二重に保存しない**（後述）。

---

## セットアップ手順

### 1. Supabase プロジェクトを作る

1. https://supabase.com にログイン（GitHub アカウントでログインできる）
2. **New project** → 名前は `affiliate-dashboard` など / Region は **Northeast Asia (Tokyo)** / プランは Free
3. できたら **SQL Editor** を開き、このリポジトリの [`sql/schema.sql`](sql/schema.sql) を**全文コピペして Run**
   - テーブル・インデックス・RLS・集計用の関数がまとめて作られる
   - 何度実行しても大丈夫（冪等）

### 2. ログイン用のユーザーを作る

このダッシュボードはログイン必須（ログインしていないと 1 行も読めない設定）。

1. Supabase の **Authentication → Users → Add user** → **Create new user**
2. 自分のメールアドレスと任意のパスワードを入れる（"Auto Confirm User" をオンに）
3. 使う人のぶんだけ同じように追加する

**あわせて、勝手に登録されないよう新規サインアップを止めておく**：
**Authentication → Sign In / Providers → Email** の **Allow new users to sign up** をオフ。

### 3. 接続情報を控える

Supabase の **Project Settings → API** にある次の 2 つ。

| 項目 | 使うもの |
|---|---|
| Project URL | `https://xxxxxxxx.supabase.co` |
| API Key | **anon public** のほう |

> `service_role` のキーは**絶対に使わない / どこにも貼らない**。RLS を無視できる管理者権限のキーなので、
> ブラウザで使う場所には置かないこと。

### 4. ダッシュボードを開く

初回アクセス時に「初期設定」画面が出るので、上の 2 つを貼り付ける。
入力値は**そのブラウザの localStorage にだけ**保存され、リポジトリには入らない。

チーム全員に同じ設定を配りたい場合だけ、[`js/config.js`](js/config.js) に直接書いてもよい
（その場合、リポジトリを見られる人には anon key が見える。データ自体は RLS とログインで守られている）。

### 5. データを入れる

「データ取込」タブに xlsx をドラッグ＆ドロップするだけ。
成果リストかクリックデータかは、中身の見出しを見て自動判定する。

## 手元で動かす

ES モジュールを使っているので `index.html` をダブルクリックしても動かない。
付属の簡易サーバーを使う（Node.js 不要）。

```bash
powershell -ExecutionPolicy Bypass -File serve.ps1
```

→ http://localhost:8080/ を開く。

## GitHub Pages で公開する

```bash
git remote add origin https://github.com/<ユーザー名>/affiliate-dashboard.git
git branch -M main
git push -u origin main
```

そのあと GitHub のリポジトリで
**Settings → Pages → Source: Deploy from a branch → Branch: `main` / `/ (root)`** を選ぶ。
数十秒で `https://<ユーザー名>.github.io/affiliate-dashboard/` が開ける。

> 成果データ・クリックデータは Supabase 側にあり、ログインしないと 1 行も読めない。

## 画面

| タブ | 内容 |
|---|---|
| サマリー | KPI（成果件数・クリック・CVR・売上・報酬・平均単価）、日次推移、ステータス／デバイス円グラフ、広告主別、アフィリエイター売上 TOP10 |
| 推移 | 日／週／月を切り替えた推移。クリック×成果の複合グラフ、売上・報酬、CVR 推移、数値テーブル |
| アフィリエイター | クリック／売上 TOP15 の棒グラフ＋全件ランキング表。行をクリックすると、その人の**流入元（リファラ）**・広告別・商品別・日別の内訳が開く |
| 商品・広告 | 商品／広告／キャンペーン／広告主／広告タイプを切り替えて集計。棒グラフ＋構成比の円グラフ＋明細表 |
| 流入元 | リファラ（ホスト単位）別のクリック・成果・CVR |
| 成果明細 | 全項目の明細をキーワード検索・ページング。CSV 出力あり |
| データ取込 | xlsx / csv の取り込みと取り込み履歴 |

共通フィルタ：**期間**（プリセット付き）／**ステータス**（承認・保留・却下をチェックで切替）／**広告主・プログラム**（複数選択）。
各表はヘッダクリックで並べ替え、主要な表は CSV 出力できる。

## データの扱い

### IPアドレス

成果リストの「最後のクリックIP」「最初のクリックIP」、クリックデータの「IP」は、
**ブラウザで読んだ時点で捨てている**。DB にも列が無い。

### 同じデータを二重に保存しない仕組み

2 段構えになっている。

1. **ファイル単位** — ファイルのバイト列の SHA-256 を `imports.file_hash` に記録している。
   まったく同じファイルを入れ直すと「既に取り込み済み」と表示してスキップする。
   （どうしても入れ直したいときは「強制的に再取込」にチェック）

2. **行単位** — 期間が一部だけ重なる別のファイルを入れても重複しない。
   - 成果データ: **注文ID が主キー**。既存の注文は行が増えるのではなく上書きされる。
     ステータスが「保留 → 承認」に変わった場合も、入れ直せば最新の状態になる。
   - クリックデータ: 一意キーが無いので、
     `日付 + アフィリエイター + 広告タイプ + 広告名 + キャンペーン + 参照URL + OS` から
     指紋（128bit ハッシュ）を作り、まったく同じ内容の行が複数あるときは通番を振って区別する。
     この指紋は同じ入力なら必ず同じ値になるので、何度入れ直しても件数は増えない。
     （実データ 10,918 行で検証済み: 指紋のユニーク数 10,779 + 通番で 10,918 行を欠損なく保持）

### タイムゾーン

元ファイルの日時は JST 表記なので、`+09:00` を明示して `timestamptz` で保存している。
集計はすべて `Asia/Tokyo` の暦日で行う。

### クリックデータの広告主

クリックのエクスポートにはプログラム名の列が無いので、取り込み画面で指定する（既定 `bestkenko`）。
成果リストの「広告主ID」（`bestkenko` / `kusuriexpress` / `unidru` / `petkusuri` …）と同じ値にすると、
広告主フィルタで両者が揃って絞られ、CVR が正しく出る。

> **CVR が出ないときは期間を確認**。クリックと成果で取り込んだ期間が重なっていないと CVR は計算できない
> （同じ期間のクリックが 0 件なら「—」と表示される）。

## 構成

```
index.html          画面の骨組み
css/app.css         スタイル（ライト／ダーク対応）
js/app.js           画面制御・各ビューの描画
js/db.js            Supabase クライアントと RPC ラッパ
js/config.js        接続先の既定値（空でよい）
js/parse.js         xlsx/csv の読み取り・IP除去・指紋の生成
js/importer.js      取り込み画面のロジック
js/charts.js        Chart.js のラッパ（線・棒・円）
js/table.js         並べ替えできる表
js/util.js          数値・日付の整形、ハッシュ、CSV出力
sql/schema.sql      Supabase 側の定義（テーブル・RLS・集計関数）
serve.ps1           手元確認用の簡易HTTPサーバー
```

外部ライブラリは CDN から読み込む（SheetJS / Chart.js / supabase-js）。npm も Node.js も不要。
